## Choosing a Sync Workflow

There is **no single official mandate** — three viable workflows coexist. Pick by your constraint, not by fashion.

| Workflow | Use when | Trade-off |
|----------|----------|-----------|
| **Rojo + VS Code** | Git-native team, CI/CD, large codebase | Filesystem-first; partially managed Rojo can leave world building in Team Create. Define which tool owns each subtree to avoid conflicting edits |
| **Script Sync** | You need Team Create + external editor | Roblox-native, resumes on restart; **syncs scripts only**, not Models/Parts. Check its current release stage, script-count limits, and known issues in the DevForum Script Sync announcements before committing a team to it |
| **Azul + Rokit + Wally** | Want external editing without Rojo's project-file overhead | Studio-first, infers structure; newer, community-maintained (check repo activity) |

Choose by filesystem ownership versus Studio-led collaboration; check current tool support and release status before adopting.

## Rojo + Rokit + Wally (git-native)

The dominant production stack for serious projects.

1. **Install the tool manager — Rokit** (successor to the deprecated Aftman):
   ```bash
   rokit add rojo-rbx/rojo
   rokit install
   ```
2. **Scaffold the project:**
   ```bash
   rojo init
   ```
   This generates `default.project.json` and a `src/` layout.
3. **Serve and connect:** run `rojo serve`, then connect from the Rojo Studio plugin. Filesystem edits sync into Studio; this is not a Studio-to-filesystem write-back workflow. Keep Rojo-managed edits on disk.
4. **Version control** the filesystem with git as you would any codebase.

VOLATILE: command surface and plugin UI can change across Rojo majors — verify against the current Rojo docs.

## Script Sync (Team Create compatible)

Roblox's built-in external-editing workflow; check its current release status and supported instance types in the official Script Sync docs. Syncs `Script`, `LocalScript`, `ModuleScript`, and `Folder` instances to `.lua`/`.luau` files on disk, supports folder-level sync, resumes automatically on Studio restart, and supports **Team Create**. Validate bidirectional script sync separately from Rojo’s filesystem-first workflow.

Limitations (look up the current list): cannot sync non-script instances (Models, Parts); no full project-structure management. Reported edge cases: "ghost instances" in Team Create, and scripts nested under non-Folder/non-Script ancestors can be silently skipped — confirm every script actually round-trips.

Use it when collaborative in-Studio editing (Team Create) is non-negotiable and you still want to edit scripts in VS Code.

## default.project.json

A JSON file mapping the on-disk tree to the Roblox DataModel — e.g. `src/server/` → `ServerScriptService`, `src/shared/` → `ReplicatedStorage`, `src/client/` → `StarterPlayer/StarterPlayerScripts`. Required by Rojo (auto-generated by `rojo init`); not needed for Azul or Script Sync, which infer structure.

Keep the realm split clean:
- `ServerScriptService` / `ServerStorage` — server-only logic and assets the client must never receive.
- `ReplicatedStorage` — shared modules and assets both realms need (kept lean; never streams).
- `StarterPlayerScripts` / `StarterGui` — client code and UI.

## Package and Build Tooling

| Tool | Role | Analogue |
|------|------|----------|
| **Rokit** | Toolchain version manager | `asdf` / `volta` |
| **Wally** | Package manager (`wally.toml`, `[dependencies]` + `[server-dependencies]`) | `npm` / `cargo` |
| **Lune** | Standalone Luau runtime for build scripts, CI, place-file manipulation | `package.json scripts` runner |
| **Argon** | Community Rojo alternative with two-way instance+property sync | — |

DURABLE: Rokit + Wally + Lune as the git-native automation trio. VOLATILE: Argon's relative maturity vs Rojo.

## AI-Assisted Creation

"Create a world" legitimately includes AI tooling. The tools below exist in some form; their release stage (Beta vs GA), limits, and availability move quickly, so check each one's status in the Assistant docs and creator roadmap before depending on it.

| Feature | Use |
|---------|-----|
| **Code Assist** | In-editor Luau completion, explanation, insertion |
| **Material Generator** | Text prompt → Material Variant with PBR maps |
| **Assistant (chat + planning mode)** | In-Studio AI chat; planning mode generates task lists; procedural model generation |
| **Studio MCP server** | Studio exposes an MCP server so external LLM agents can drive Studio |
| **Assistant playtest agent** | Automated QA-style playtesting against the plan, code, data model, logs, and playable character |
| **Avatar Auto-Setup** | AI avatar rigging; check the output rig before shipping |
| **Texture Generator** | Text prompt → ColorMap texture for MeshParts; check current resolution, map types, and generation caps |
| **4D Objects / generative 3D** | Announced; confirm shipping before depending on it |

Practical flow: use the material and texture generators to dress greyboxed geometry fast, Code Assist for boilerplate, and the Studio MCP server when you want an external agent to manipulate the place — but keep human authority over architecture and economy logic (the AI is for drafting, not for trusted decisions).

VOLATILE: every AI feature's status, limits, and availability — verify against the current creator roadmap and Assistant docs.
