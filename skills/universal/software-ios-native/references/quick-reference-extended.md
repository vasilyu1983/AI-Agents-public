## Agent tooling & build

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Local-dev launcher pair** | `scripts/run-local-ios-dev.sh` + `scripts/stop-local-ios-dev.sh` | Pair a run script that boots the local backend (Next.js, Cloudflare Worker, Express) with a stop script that uses a persisted `.local-worker.pid` to kill exactly what was started. Apply **two defensive guards** in run: grep the env file for `localhost:` before xcodegen, and grep the generated `Info.plist` for `localhost` after — abort on either miss. Both guards together make a "local-dev build that silently hits production" un-launchable. Persist the booted simulator's UDID to `.simulator-udid` so stop terminates exactly that simulator (never `pkill -f Simulator`, which shotguns unrelated sims). Keep the pair in each app repo's own `scripts/` directory. |
| **Generated files that the pbxproj references** | Commit them, or regenerate in a CI hook | Anything `scripts/generate-xcodeproj.sh` produces at local-build time (Info.plist, locale manifests, exported JSONs) must exist on CI by one of two paths: committed to git (use `git add -f` if the enclosing folder is gitignored), or regenerated by a CI-side hook. Relying on "developers always regenerate before committing" silently breaks Xcode Cloud and any fresh-clone CI |
| **Gitignored folder with some tracked files** | Treat as a CI landmine | Once a file is tracked, `.gitignore` doesn't untrack it — but any *new* file added to the folder stays untracked. Mixed state is invisible locally and blows up on Xcode Cloud. Either commit all generated outputs explicitly with `git add -f`, or remove the folder from `.gitignore` and let `git status` tell you when they drift |
| **Xcode Cloud CI hook** | `ci_scripts/ci_post_clone.sh` (convention, not config) | Runs after checkout, before dependency resolution. Right place to synthesize `.env` shims from Xcode Cloud environment variables and call local generators (e.g., `scripts/generate-infoplist.sh`). Xcode Cloud checks out only the current repo, so sibling-repo-dependent local scripts cannot be reused verbatim — factor out the CI-safe subset |
| **TARGETED_DEVICE_FAMILY change to "1" (iPhone only)** | Requires a fresh archive + App Store Connect build attachment | Changing it in `project.yml` is not enough; the value is baked into the binary. The iPad screenshot requirement in App Store Connect only clears once the new iPhone-only build is uploaded and attached to the version |

## StoreKit & billing

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Paid Apps Agreement (#1 invisible blocker)** | State `.loaded` + `subscriptionProducts.isEmpty` with every per-product field correct | Apple's StoreKit backend returns an empty array for every `Product.products(for:)` query when the account-level **Paid Apps Agreement** is not `Active` — regardless of per-subscription status. No specific error code, just silent empty results. Check this **first** before any subscription-level or device-level diagnosis. Open [https://appstoreconnect.apple.com/business](https://appstoreconnect.apple.com/business) and verify the Paid Apps row shows **Active** in green. Common stuck states: `Pending User Info` (tax form missing or banking in Apple's 24-hour processing queue), `Not Started`, `Expired`. See [software-mobile → app-store-connect-checklist.md → Phase 5](../../software-mobile/references/app-store-connect-checklist.md) for the full decision table, W-8BEN UK field guide, and realistic 20-30 hour activation timeline. |
| **ASC `Missing Metadata` diagnosis** | State `.loaded` + `subscriptionProducts.isEmpty` on paywall | Products exist in ASC but every required field (prices, localization, review screenshot) is not yet filled. See [software-mobile → app-store-connect-checklist.md → Unblocking `Missing Metadata`](../../software-mobile/references/app-store-connect-checklist.md) for the full workflow. |
| **Review screenshot preparation** | sRGB 8-bit RGB PNG at 72 DPI, 1284 × 2778 | iPhone screenshots are Display P3 / 16-bit / RGBA / 144 DPI — ASC rejects every one. Use the Pillow profile-to-profile recipe in the checklist. `sips --matchTo` only updates the flag, does not convert colors. |
| **Accounting currency with locale-aware formatting** | `NumberFormatter` + explicit `currencyCode` | For backend-denominated currencies that don't match the user's locale (e.g., referral rewards paid in GBP regardless of storefront). Set `numberStyle = .currency`, `currencyCode = "GBP"`, `locale = .current` — preserves the currency symbol while gaining locale-correct thousands and decimal separators. Never use `String(format: "£%.2f", …)` — that hardcodes both the symbol and the separator conventions. |

## l10n & backend locale

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Backend locale, prose vs structural data, template split** | Strings, plurals, catalogs, and the translation pipeline are owned by [software-localisation](../../software-localisation/SKILL.md) | Client contract, server locale priority, and Pattern A/B for backend-generated prose: [backend-generated-content-i18n.md](../../software-localisation/references/backend-generated-content-i18n.md). iOS keeps only the platform mechanics below (formatters, catalogs) |
| **Locale-aware time formatting** | `DateFormatter.dateFormat(fromTemplate: "jm", options: 0, locale: locale)` | The "jm" skeleton lets the system pick 12h vs 24h based on *both* the locale's convention AND the user's `Settings → General → Date & Time → 24-Hour Time` override. Never hand-roll `if locale == "en-US"` branches. Cache per-locale `DateFormatter` instances in `NSCache<NSString, DateFormatter>` because `DateFormatter` init is expensive inside list rendering |
| **Raw locale-formatted currency is wrong for backend currency** | Use `NumberFormatter` with explicit `currencyCode` + `locale = .current` | For backend-denominated currencies that don't match the user's storefront (e.g., referral rewards in GBP regardless of locale), the pattern is `numberStyle = .currency`, `currencyCode = "GBP"`, `locale = .current` — preserves the currency symbol while gaining locale-correct separators. Never hardcode `String(format: "£%.2f", …)` — that locks both the symbol and separator conventions |

## Auth & push — detailed rows

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Push delegate isolation** | Match the imported SDK requirement and callback contract | Transfer Sendable routing values before hopping UI state to `@MainActor`; do not infer a universal delegate fix from a private symbol. See [delegate boundary guidance](swiftui-observation-concurrency.md#nonisolated-async-delegate-methods--nested-mainactorrun). |
| **`Task { }` isolation** | Inherits actor context where the closure is formed; use explicit `Task { @MainActor in ... }` when bridging from a nonisolated callback | `Task.detached` breaks actor inheritance. A task created inside a main-actor-isolated method may access that state directly; one created in a nonisolated delegate or completion handler must hop explicitly. See [`references/swiftui-observation-concurrency.md` → `Task { }` inherits its actor context](swiftui-observation-concurrency.md#task---inherits-its-actor-context) |
| **`actor` vs `@MainActor final class`** | Choose isolation by state ownership and work | Main-actor callers resume on the main actor after `await`; keep CPU-heavy work off it. See [actor ownership guidance](swiftui-observation-concurrency.md#actor--mainactor-final-class-refactoring-guidance). |
| **`@Sendable async` closure awaited from `@MainActor`** | Return results to the isolated caller | `@Sendable` does not choose an executor. Add `@MainActor` only when the closure body needs UI state; caller isolation survives `await`. See [closure guidance](swiftui-observation-concurrency.md#sendable-async-closure-isolation-footgun). |
| **`SCNView` in `UIViewRepresentable`** | Create initial scene once; apply changed inputs in `updateUIView` | Prefer incremental updates to avoid resetting interaction state; a no-op update method is correct only for immutable inputs. See [representable lifecycle](swiftui-observation-concurrency.md#scnview-reassignment-in-updateuiview-anti-pattern). |
| **Push-open ownership** | One owner for pending-route staging and consumption | Cold-start resume should not race route staging, auth bootstrap, and direct route-open calls. Cold-start auth guard in `handleOpenedPush`: if `session.isAuthenticated` is false, stage the route and return — let bootstrap own the resume |
| **Push preference sync** | `@AppStorage` for instant UI + backend POST for cron filtering | Local-only toggles mean backend crons can't respect user preferences |
| **Push entitlements** | Inspect `aps-environment` in the signed exported app and selected profile | APNs environment follows provisioning/distribution selection, not the build-configuration name. Development provisioning uses `development`; push-enabled TestFlight/App Store exports require `production`. |
| **APNs environment proof** | Xcode-on-device -> `sandbox`; TestFlight/App Store -> `production` | Do not treat local debug push success as release proof; verify both paths explicitly |
| **Export gate for TestFlight** | Inspect final exported `.app` entitlements and its provisioning profile | Xcode can re-sign during distribution; push-enabled exports require `production`, and release exports must not enable debugging. See [distribution gate](ios-release-and-compliance.md#release-signing-and-distribution). |
| **Backend push routing** | Store and route per-device push environment | Device rows should be authoritative; any global env var should remain a production-safe fallback. Detailed schema, pre-flight gates, and failure modes in [`software-mobile/references/push-notifications-guide.md` → Per-device APNs environment routing](../../software-mobile/references/push-notifications-guide.md#per-device-apns-environment-routing) |
| **Push QA loop** | Deterministic server-side send over waiting for cron | Validate payload, newest device row, APNs response, and device-visible result in one loop |

## Canvas, immersive screens & l10n hygiene

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Canvas & visualization** | | |
| Canvas data views | Start `animatedProgress` at 1 | Data loads after `.onAppear`; starting at 0 leaves Canvas empty |
| Canvas gestures | `DragGesture` + `SpatialTapGesture` overlay | Compute hit targets from coordinates, not invisible tap areas |
| Type checker crashes | Split complex views into helper functions | `.overlay { if }` and tuple `ForEach` are common triggers |
| **Immersive screens & sheets** | | |
| Immersive viz screens | `ZStack { bg; scene; controls; .sheet(persistent) }` | No scroll, no card wrappers, sheet peek + bottom padding |
| Persistent sheet | `.presentationBackgroundInteraction(.enabled(upThrough: .medium))` | Allows gestures on viz while sheet is visible |
| Viz state: inspect (chart) | Parent `@Binding` for zoom/drag | Controls strip reads/writes same state |
| Viz state: orbit (3D) | Parent `@State` + callback | SceneKit drives camera, reports back |
| Viz state: navigate (map) | Internal `@State` | Zero-latency gesture response for spatial pan/zoom |
| Parent-initiated reset | Reset token (`Int` incremented by parent) | View `.onChange(of: token)` resets internal state |
| Viz overlay controls | `Picker(.segmented)` + `Menu` | Native controls, not custom material-backed buttons |
| Dense diagram controls | Zoom in/out/reset + semantic filters | When gates, labels, or markers overlap, expose inspection controls before redrawing the whole chart |
| Diagram detail placement | Below-chart summary or persistent sheet | Do not cover the diagram with popups or bottom overlays that block inspection |
| Canvas animation (glow/pulse) | `TimelineView(.animation)` wrapping Canvas | Gate behind condition to avoid 30fps waste |
| Square Canvas sizing | `.aspectRatio(1, contentMode: .fit)` | Prevents dead space in taller-than-wide frames |
| Viz export/share | `ImageRenderer` + `proposedSize` | Static export view, no gestures or parallax |
| Immersive shared state | `@Observable` class via `@State` + `@Bindable` | Avoids 15+ `@Binding` prop-drilling |
| Year/ID in `navigationTitle` | String concat: `name + " " + String(year)` | No `verbatim:` overload — interpolation resolves to `LocalizedStringKey` |
| Multiple sheets | Multiple `.sheet` modifiers on one view | iOS 16.4+; each gated by its own `Optional` property |
| Grid cell width | `.frame(maxWidth: .infinity)` inside `LazyVGrid` cells | Content doesn't stretch automatically; without this, columns are unequal |
| Help/detail row width | `.frame(maxWidth: .infinity, alignment: .leading)` | Leading `VStack` rows shrink to intrinsic width unless explicitly stretched, making peer containers uneven |
| Grid cell clip shape | `RoundedRectangle` not `Capsule` | Capsule pinches at wide aspect ratios in stretched grid cells |
| Deleting `.pbxproj` files | Remove `PBXBuildFile`, `PBXFileReference`, group child, and sources entry | Missing any one leaves stale references or build warnings |
| Sheet swapping | Set `item` to `nil`, delay ~350ms, set new value | `.sheet(item:)` can't swap in one frame; `onDismiss` + state = loop |
| l10n in plain enums | Call l10n in View body, not enum methods | `@MainActor` l10n store can't be called from nonisolated enum funcs |
| l10n catalog integrity | Key and value parity, generated catalogs, large-file edits | Owned by [software-localisation](../../software-localisation/references/backend-generated-content-i18n.md#catalog-integrity-for-native-apps) |

## Swift 6.2+ / Xcode 26+ additions

| Task | Default Picks | Notes |
|------|---------------|-------|
| Default actor isolation (new projects) | `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` in Xcode 26+ | App targets benefit most; library targets stay `nonisolated`. Flip flag, triage leaf types, mark non-UI `nonisolated`/`@concurrent`, remove defensive `MainActor.run` wraps. Do NOT bulk-silence with `@preconcurrency` |
| `withAnimation` in `@MainActor` | Known iOS 26 regression | Hoist `withAnimation` outside `@MainActor` body or wrap in `Task { @MainActor in withAnimation(…) { … } }`; verify on iOS 26.0 / 26.2 / 26.4 |
| `SubscriptionStatus.all` stale after subscription change | Xcode 26 StoreKit 2 bug | Query `Product.SubscriptionInfo.Status` directly after `Transaction.updates` tick; don't trust cached `all` array |
| `AnyView` avoidance | Type erasure defeats diffing | Use `@ViewBuilder`, `some View`, or `Group + if/switch` instead |
| `@ObservedObject` in new code | Legacy pre-iOS-17 pattern | Replace with `@Observable` + `@Bindable`; `@StateObject` → `@State`; `@Published` unnecessary on `@Observable` |
| `NavigationView` deprecation | Replaced | `NavigationStack` for push/pop; `NavigationSplitView` for multi-column |
| `.id(UUID())` force refresh | Anti-pattern | Causes full re-init + retained subscriptions; drive refreshes from state |
| Combine subscription lifecycle | Memory leak #1 | Every `sink`/`assign` into `.store(in: &cancellables)` or cancel in `onDisappear`/`deinit` |
| Coordinator-pattern navigation | `NavigationStack` + enum routes | `@Observable AppCoordinator` with `path`; inject via `@Entry`; one coordinator per module |
