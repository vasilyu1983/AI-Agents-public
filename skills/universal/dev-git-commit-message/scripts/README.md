# commit_validator.py

Stdlib-only Python CLI for validating and linting commit messages against bundled Conventional Commits and style defaults. It does not load `config.yaml`; target-repository overrides need separate review. No external dependencies — runs with any Python 3.9+ installation.

## Purpose

Gives developers and CI pipelines fast, reproducible answers to three core questions:

1. **Validate** — Does a single commit message pass Conventional Commits rules? What is wrong, and what should it be instead?
2. **Lint** — How healthy is a commit history? Per-message PASS/WARN/FAIL with a summary of the most common violations.
3. **Report** — A full Markdown quality report with executive summary, violation breakdown, per-commit table, and an attention list for non-passing commits.

## Quick Start

Run from the `dev-git-commit-message/` directory:

```bash
# Validate a single message — PASS
python scripts/commit_validator.py validate --message "feat(auth): add refresh token rotation"

# Validate a single message — FAIL (no type prefix)
python scripts/commit_validator.py validate --message "update"

# Validate a single message — FAIL (banned word)
python scripts/commit_validator.py validate --message "fix stuff"

# Validate a single message — WARN (non-imperative tense)
python scripts/commit_validator.py validate --message "feat(ui): added dark mode toggle"

# Plain imperative subject, no type prefix — PASS only with --no-type-prefix
python scripts/commit_validator.py validate --no-type-prefix --message "Add refresh token rotation"

# Lint a batch of commit messages from a JSON history file
python scripts/commit_validator.py lint --input data/sample-commit-history.json

# Lint without ANSI colour (useful for CI logs)
python scripts/commit_validator.py --no-color lint --input data/sample-commit-history.json

# Full Markdown report printed to stdout
python scripts/commit_validator.py report --input data/sample-commit-history.json

# Full Markdown report written to a file
python scripts/commit_validator.py report --input data/sample-commit-history.json --output /tmp/commit-report.md
```

## Input Format

The `lint` and `report` subcommands require a nonempty JSON array of commit objects. `message` is required and all supplied fields listed below must be strings; malformed records fail before lint/report output:

```json
[
  {
    "hash":    "a1b2c3d",
    "message": "feat(auth): add refresh token rotation",
    "author":  "Example Contributor",
    "date":    "2026-03-18"
  }
]
```

| Field | Required | Notes |
|-------|----------|-------|
| `message` | yes | The full commit message; type, summary, and length rules apply to the first line only |
| `hash` | no | Short 7-character hash; shown in lint/report output |
| `author` | no | Author username or display name |
| `date` | no | ISO date string (YYYY-MM-DD); shown in report detail |

See `data/sample-commit-history.json` for a 20-commit example with a realistic mix of passing, warning, and failing messages.

## Validation Rules

These are bundled policy defaults. The specification permits additional types and does not require these case, length, imperative-mood, or attribution rules. A space after the subject colon is required.

| Rule | Threshold | Status |
|------|-----------|--------|
| Type prefix required | `<type>: <summary>` or `<type>(<scope>): <summary>` | FAIL |
| Valid type | feat, fix, perf, refactor, docs, test, build, ci, chore, style, revert | FAIL |
| Type must be lowercase | — | FAIL |
| Scope, if present | Nonempty lowercase kebab-case | FAIL |
| No trailing period on summary | — | FAIL |
| Banned summary phrases | update, wip, misc, update stuff, fix stuff, change code | FAIL |
| No tool/AI attribution | generated by, via claude, via copilot, chatgpt, ai assistant in subject/body; AI-tool trailers other than `Assisted-by:` (recommended default), `Claude-Session:` and `Audit-*` | FAIL |
| Accepted as-is | message body, `BREAKING CHANGE:` footer, git default `Revert "..."` subject, `Signed-off-by:` and other non-AI trailers | — |
| Subject line hard limit | ≤72 chars | FAIL |
| Imperative mood | no past/present-continuous first word (added, fixing, …) | WARN |
| Subject line soft limit | ≤50 chars preferred | WARN |

### Plain-subject opt-out

`--no-type-prefix` (accepted by `validate`, `lint` and `report`) is for repositories whose convention is short imperative subjects with no `type(scope):` prefix. It skips only the type/scope rule: a subject that is not Conventional Commits is checked as a plain summary (length, trailing period, banned phrases, imperative mood), and trailer rules are unchanged. A subject that does start with a valid lowercase type (`feat(auth): ...`) is still validated as Conventional Commits. There is no config-file default because the script does not load `config.yaml`; pass the flag explicitly.

## Tests

```bash
python3 scripts/test_commit_validator.py
```

Covers the `--no-type-prefix` opt-out (plain subject fails without it, passes with it; length, period and trailer rules unchanged), body + `BREAKING CHANGE:` footer, git revert, `Assisted-by:` / `Claude-Session:` / `Audit-*` / `Signed-off-by:` trailers, and that AI `Co-authored-by:` and unknown AI trailers and missing type prefixes still fail.

## Exit Codes

| Code | Meaning |
|------|---------|
| `0` | `validate`/`lint`: all messages PASS or WARN; `report`: report generated, even if it records violations |
| `1` | `validate`/`lint`: one or more messages FAIL; any command: file/schema error |

Argument parsing errors exit 2. File errors name the affected path. Empty histories are rejected because no message was checked.
