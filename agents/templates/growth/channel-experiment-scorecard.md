# Growth Template: Channel Experiment Scorecard

Use when the team has several possible channels and needs one primary test.

## Score Each Channel

Rate 1-5. Do not average blindly; a channel with a zero in proof fit or measurement should not be primary.

| Criterion | Question |
|---|---|
| Audience access | Can we reach the exact ICP without broad targeting? |
| Problem timing | Does the channel expose users near the trigger event? |
| Proof fit | Can the channel carry the proof asset needed for trust? |
| Speed | Can we learn inside the current planning window? |
| Cost | Can we run the test without burning the budget before learning? |
| Measurement | Can we connect the channel to activation-quality behavior? |
| Founder advantage | Does the team have a non-obvious edge in this channel? |

## Output Contract

```text
Channel decision:
- Primary channel:
- Backup channel:
- Channels explicitly rejected:
- Required asset:
- Activation-quality metric:
- Attribution method:
- Minimum viable spend or time budget:
- Stop condition:

- Next route if the channel fails:
```

## Guardrails

- Do not choose more than one primary channel.
- Do not recommend a channel because it is popular; name why this product has an edge there.
- Do not call a traffic increase a win unless activation quality also improves.
- If no channel can be measured, instrumentation is the first experiment.
