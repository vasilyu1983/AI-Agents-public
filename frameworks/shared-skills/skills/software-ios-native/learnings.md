# Learnings

- **2026-07-11**: Deep-audit pass (v1.0 → v1.1). The skill's factual base was already strong (iOS 26 SDK mandate, Swift 6.2 concurrency guidance, and trap table all verified accurate), but several hardcoded Xcode point-release numbers (26.3, 26.4) had aged into stale-sounding claims and the skill had zero mention of the WWDC26 (June 2026) iOS 27 / Xcode 27 beta announcement, risking a reader treating "26" as still-latest without realizing a beta successor existed. Fix: softened point-release mentions to "current stable, re-verify each session" phrasing (SKILL.md, references/agentic-ios-tooling.md, references/runtime-proof-and-prompts.md, references/ios-app-conveyor.md, data/sources.json), added an explicit "Version Currency" section to SKILL.md distinguishing shipped (iOS 26.x/Xcode 26.6/Swift 6.3) from announced-not-shipped (iOS 27/Xcode 27/Swift 6.4, beta only), and added an "Expert Judgment Calls" section (SwiftUI-vs-UIKit gate, strict-concurrency adoption strategy, SPM-vs-CocoaPods judgment, modularization threshold, TestFlight/phased-release discipline) that the skill implied but never stated outright. Lesson for future audits of fast-moving platform skills: grep every hardcoded point-release number skill-wide before trusting a single file's framing, and check the trailing edge (next major version's beta status) even when the skill's headline facts are still correct — staleness shows up first in point releases and unannounced successors, not in the big claims.
