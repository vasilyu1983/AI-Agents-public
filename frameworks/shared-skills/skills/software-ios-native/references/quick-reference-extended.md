# Quick Reference — Extended Rows

Rows here were moved from the main `SKILL.md` Quick Reference table. They retain full detail; use them when the one-liner summary in SKILL.md isn't sufficient.

## Agent tooling & build

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Local-dev launcher pair** | `scripts/run-local-ios-dev.sh` + `scripts/stop-local-ios-dev.sh` | Pair a run script that boots the local backend (Next.js, Cloudflare Worker, Express) with a stop script that uses a persisted `.local-worker.pid` to kill exactly what was started. Apply **two defensive guards** in run: grep the env file for `localhost:` before xcodegen, and grep the generated `Info.plist` for `localhost` after — abort on either miss. Both guards together make a "local-dev build that silently hits production" un-launchable. Persist the booted simulator's UDID to `.simulator-udid` so stop terminates exactly that simulator (never `pkill -f Simulator`, which shotguns unrelated sims). Reference implementations: `cosmic-swift/scripts/{run,stop}-local-ios-dev.sh` and `cosmic-copilot-ios/scripts/{run,stop}-local-ios-dev.sh`. |
| **Generated files that the pbxproj references** | Commit them, or regenerate in a CI hook | Anything `scripts/generate-xcodeproj.sh` produces at local-build time (Info.plist, locale manifests, exported JSONs) must exist on CI by one of two paths: committed to git (use `git add -f` if the enclosing folder is gitignored), or regenerated by a CI-side hook. Relying on "developers always regenerate before committing" silently breaks Xcode Cloud and any fresh-clone CI |
| **Gitignored folder with some tracked files** | Treat as a CI landmine | Once a file is tracked, `.gitignore` doesn't untrack it — but any *new* file added to the folder stays untracked. Mixed state is invisible locally and blows up on Xcode Cloud. Either commit all generated outputs explicitly with `git add -f`, or remove the folder from `.gitignore` and let `git status` tell you when they drift |
| **Xcode Cloud CI hook** | `ci_scripts/ci_post_clone.sh` (convention, not config) | Runs after checkout, before dependency resolution. Right place to synthesize `.env` shims from Xcode Cloud environment variables and call local generators (e.g., `scripts/generate-infoplist.sh`). Xcode Cloud checks out only the current repo, so sibling-repo-dependent local scripts cannot be reused verbatim — factor out the CI-safe subset |
| **TARGETED_DEVICE_FAMILY change to "1" (iPhone only)** | Requires a fresh archive + App Store Connect build attachment | Changing it in `project.yml` is not enough; the value is baked into the binary. The iPad screenshot requirement in App Store Connect only clears once the new iPhone-only build is uploaded and attached to the version |

## StoreKit & billing

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Paid Apps Agreement (#1 invisible blocker)** | State `.loaded` + `subscriptionProducts.isEmpty` with every per-product field correct | Apple's StoreKit backend returns an empty array for every `Product.products(for:)` query when the account-level **Paid Apps Agreement** is not `Active` — regardless of per-subscription status. No specific error code, just silent empty results. Check this **first** before any subscription-level or device-level diagnosis. Open [https://appstoreconnect.apple.com/business](https://appstoreconnect.apple.com/business) and verify the Paid Apps row shows **Active** in green. Common stuck states: `Pending User Info` (tax form missing or banking in Apple's 24-hour processing queue), `Not Started`, `Expired`. See [software-mobile → app-store-connect-checklist.md → Phase 5](../../software-mobile/references/app-store-connect-checklist.md) for the full decision table, W-8BEN UK field guide, and realistic 20-30 hour activation timeline. |
| **ASC `Missing Metadata` diagnosis** | State `.loaded` + `subscriptionProducts.isEmpty` on paywall | Products exist in ASC but every required field (prices, localization, review screenshot) is not yet filled. See [software-mobile → app-store-connect-checklist.md → Unblocking `Missing Metadata`](../../software-mobile/references/app-store-connect-checklist.md) for the full workflow. |
| **Review screenshot preparation** | sRGB 8-bit RGB PNG at 72 DPI, 1284 × 2778 | iPhone screenshots are Display P3 / 16-bit / RGBA / 144 DPI — ASC rejects every one. Use the Pillow profile-to-profile recipe in the checklist. `sips --matchTo` only updates the flag, does not convert colors. |
| **Accounting currency with locale-aware formatting** | `NumberFormatter` + explicit `currencyCode` | For backend-denominated currencies that don't match the user's locale (e.g., referral rewards paid in GBP regardless of storefront). Set `numberStyle = .currency`, `currencyCode = "GBP"`, `locale = .current` — preserves the currency symbol while gaining locale-correct thousands and decimal separators. Never use `String(format: "£%.2f", …)` — that hardcodes both the symbol and the separator conventions. |

## l10n & backend locale

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Backend locale propagation** | `APIClient.currentLocale` + inject `?locale=` query + `Accept-Language` header on every request | Don't rely on stored profile locale server-side. Explicit query-param signals win over header signals and stored-profile signals so the client's *current* picker selection is honored even if the user hasn't yet persisted it. Priority at the server: `?locale=` > `Accept-Language` > stored profile. Propagate locale changes via `LocalizationStore.propagateLocaleToAPIClient()` on every picker change so mid-session locale switches don't leak stale cached variants |
| **Locale-aware time formatting** | `DateFormatter.dateFormat(fromTemplate: "jm", options: 0, locale: locale)` | The "jm" skeleton lets the system pick 12h vs 24h based on *both* the locale's convention AND the user's `Settings → General → Date & Time → 24-Hour Time` override. Never hand-roll `if locale == "en-US"` branches. Cache per-locale `DateFormatter` instances in `NSCache<NSString, DateFormatter>` because `DateFormatter` init is expensive inside list rendering |
| **Backend prose vs structural data** | Localize structural data client-side via enum helpers; translate prose server-side | iOS renders sign/planet/aspect names via `CelestialNames.sign()/planet()/aspect()` from the backend's English keywords — zero backend translation needed for pure structured data (chart positions, house cusps, aspect types). Only generated prose (interpretations, descriptions, narratives) needs backend translation. Recognizing this distinction prevents writing unnecessary backend translators and is one of the cleanest wins during an i18n audit |
| **Template split for interpolated prose** | Split `"Moon is Void until 4:32 PM. Consider..."` → translate `prefix` + `suffix` template separately, inject time verbatim | Never cache a prose string containing a runtime value (user name, absolute time, date). Each unique interpolation explodes the cache key space. The fix: regex out the variable portion, translate only the bounded template, re-inject the variable fragment after translation. Same pattern applies to iOS client-side if you ever build a client translation layer |
| **Raw locale-formatted currency is wrong for backend currency** | Use `NumberFormatter` with explicit `currencyCode` + `locale = .current` | For backend-denominated currencies that don't match the user's storefront (e.g., referral rewards in GBP regardless of locale), the pattern is `numberStyle = .currency`, `currencyCode = "GBP"`, `locale = .current` — preserves the currency symbol while gaining locale-correct separators. Never hardcode `String(format: "£%.2f", …)` — that locks both the symbol and separator conventions |

## Auth & push — detailed rows

| Task | Default Picks | Notes |
|------|---------------|-------|
| **Push delegate isolation** | `@unchecked Sendable` class + `@MainActor` async `UNUserNotificationCenterDelegate` methods | Known iOS / SwiftUI crash path when `nonisolated async` delegate methods perform nested `await MainActor.run { ... }`. The nested hop violates the continuation-epilogue main-thread contract and fires `UIApplication.m:3426 _performBlockAfterCATransactionCommitSynchronizes:` "Call must be made on main thread". Full pattern, mechanism, and fix in [`references/swiftui-observation-concurrency.md` → `nonisolated async` delegate methods + nested `MainActor.run`](swiftui-observation-concurrency.md#nonisolated-async-delegate-methods--nested-mainactorrun) |
| **Bare `Task { }` isolation** | `Task { @MainActor [weak self] in ... }` from `@MainActor` classes | Bare `Task { }` in Swift 5.7+ with `StrictConcurrency` runs on the global executor and does NOT inherit the enclosing class's `@MainActor`. Mutating any `@Observable` property inside crashes the same way as the delegate-method footgun. Affects cooldown timers, StoreKit `Transaction.updates` loops, debounced flush schedulers, post-`Task.sleep` state resets. See [`references/swiftui-observation-concurrency.md` → Bare `Task { }` isolation](swiftui-observation-concurrency.md#bare-task---does-not-inherit-mainactor) |
| **`actor` vs `@MainActor final class`** | Prefer `@MainActor final class` when all consumers are `@MainActor` | The `@MainActor → actor → @MainActor` round-trip via `await` introduces resumption ambiguity where the post-await tail can land on the actor's executor. Promote `APIClient`, cache, billing helpers, auth services, etc. to `@MainActor final class`. Keep real `actor` only for types genuinely coordinating multiple non-`@MainActor` contexts. See [`references/swiftui-observation-concurrency.md` → `actor` → `@MainActor final class`](swiftui-observation-concurrency.md#actor--mainactor-final-class-refactoring-guidance) |
| **`@Sendable async` closure awaited from `@MainActor`** | Retype as `@MainActor async` closure | `@Sendable async` closures awaited from `@MainActor` do NOT reliably resume on main. Common in analytics/logging SDK `RequestExecutor` typealiases. Fix: replace `@Sendable` with `@MainActor` on the closure type. See [`references/swiftui-observation-concurrency.md` → `@Sendable async` closure isolation footgun](swiftui-observation-concurrency.md#sendable-async-closure-isolation-footgun) |
| **`SCNView` in `UIViewRepresentable`** | Build scene once in `makeUIView`, `updateUIView` is a no-op | Reassigning `view.scene = scene` in `updateUIView` schedules a CATransaction commit on SceneKit's render server thread, which calls back into UIKit off-main and crashes. For scenes that genuinely need incremental updates, use a `@MainActor Coordinator` that owns the scene and mutates nodes in place. See [`references/swiftui-observation-concurrency.md` → `SCNView` reassignment anti-pattern](swiftui-observation-concurrency.md#scnview-reassignment-in-updateuiview-anti-pattern) |
| **Push-open ownership** | One owner for pending-route staging and consumption | Cold-start resume should not race route staging, auth bootstrap, and direct route-open calls. Cold-start auth guard in `handleOpenedPush`: if `session.isAuthenticated` is false, stage the route and return — let bootstrap own the resume |
| **Push preference sync** | `@AppStorage` for instant UI + backend POST for cron filtering | Local-only toggles mean backend crons can't respect user preferences |
| **Push entitlements** | `aps-environment` key in `.entitlements` | Required for APNs; `development` for debug, `production` auto-set by Xcode for release |
| **APNs environment proof** | Xcode-on-device -> `sandbox`; TestFlight/App Store -> `production` | Do not treat local debug push success as release proof; verify both paths explicitly |
| **Archive gate for TestFlight** | `codesign -d --entitlements - "/path/to/App.app" \| grep -A1 aps-environment` | Run on the archived `.app` before upload; it must print `production` |
| **Backend push routing** | Store and route per-device push environment | Device rows should be authoritative; any global env var should remain a production-safe fallback. Detailed schema, pre-flight gates, and failure modes in [`software-mobile/references/push-notifications-guide.md` → Per-device APNs environment routing](../../software-mobile/references/push-notifications-guide.md#per-device-apns-environment-routing) |
| **Push QA loop** | Deterministic server-side send over waiting for cron | Validate payload, newest device row, APNs response, and device-visible result in one loop |
