# Primitive: TOC Thinking Processes (TP) — Umbrella

**Source**: Goldratt (1994), *It's Not Luck*; Dettmer 2007, *The Logical Thinking Process*; Scheinkopf 1999, *Thinking for a Change*.

## Definition

The TOC Thinking Processes (TP) are a suite of five logic-based diagrams that collectively answer three strategic questions:

1. **What to change?** → Current Reality Tree (CRT, primitive 05)
2. **What to change to?** → Evaporating Cloud (EC, primitive 04) + Future Reality Tree (FRT, primitive 06)
3. **How to cause the change?** → Prerequisite Tree (PRT, primitive 07) + Transition Tree (TT, primitive 08)

The Thinking Processes are most powerful when used as a complete sequence. They are also useful individually when only one question needs answering.

## The Full Sequence

```
Observe UDEs
  ↓
Current Reality Tree (CRT)
  → "What is the core problem?"
  ↓
Evaporating Cloud (EC)
  → "What conflict perpetuates the core problem? What assumption can we challenge?"
  ↓
Future Reality Tree (FRT)
  → "If we inject this change, will it produce the desired effects? Any new UDEs?"
  ↓
Prerequisite Tree (PRT)
  → "What obstacles stand in the way? What intermediate objectives do we need?"
  ↓
Transition Tree (TT)
  → "What specific actions, in what order, with what logic?"
```

## When to Use Each Subset

| Situation | Tools |
|-----------|-------|
| Root cause unclear; multiple UDEs | CRT only |
| Conflict blocking decision or progress | EC only |
| Solution identified; need to validate it | FRT only |
| Strategy agreed; need implementation plan | PRT + TT |
| Full strategic change initiative | All five in sequence |

## Logic Types in the Thinking Processes

| Tool | Logic Type | Core Question |
|------|-----------|--------------|
| CRT | Sufficiency ("If…Then") | What causes these effects? |
| EC | Necessity ("In order to…") | What conflict drives the core problem? |
| FRT | Sufficiency ("If…Then") | Will this injection produce the desired effects? |
| PRT | Necessity ("In order to…") | What must be achieved first? |
| TT | Necessity ("In order to…") | What specific action must happen next? |

## Scrutiny Categories (for logic verification)

Dettmer's eight "Categories of Legitimate Reservation" (CLRs) are the formal tests for each arrow in any TP diagram:

1. Clarity — is the entity clearly stated?
2. Entity Existence — does the entity actually exist?
3. Causality Existence — does the cause actually produce the effect?
4. Cause Insufficiency — is the cause sufficient on its own?
5. Additional Cause — could another cause produce the effect independently?
6. Cause-Effect Reversal — is the arrow backwards?
7. Predicted Effect Existence — can the predicted effect be confirmed?
8. Tautology — is the logic circular?

Use CLRs to challenge any arrow in a tree that feels wrong before accepting it.

## When to Use Only Part of the Sequence

- **CRT only**: fast diagnosis when the solution space is already known and stakeholders just need alignment on root cause.
- **EC only**: a team is deadlocked; the conflict is the blocking issue; no full diagnosis needed.
- **FRT only**: a solution is already proposed and the risk is "will it work and what are the side effects?"
- **PRT + TT only**: strategy is agreed; the risk is implementation failure.

## Failure Modes

| Failure | Root Cause | Fix |
|---------|-----------|-----|
| Using TP as a documentation exercise | Trees built, never acted on | Tie each tree to a specific decision or action |
| Skipping CRT; jumping to FRT | Solving the wrong problem | Always diagnose before designing |
| Running TP in isolation | One person builds the tree without team input | TP is designed for facilitated group work; surface disagreements through the logic |
| Using all five tools when one is sufficient | Overhead exceeds value | Match tool to question; don't build a CRT when you already know the core problem |
| Trees grow without bound | No scope discipline | Scope each tree to a specific domain or decision; use separate trees for separate systems |
