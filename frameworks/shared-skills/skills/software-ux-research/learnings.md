Two concrete errors found and fixed: (1) `usability-testing-guide.md` stated "85% of issues found with 5 users" as a bare fact — it is the Nielsen/Landauer model result (λ≈0.31, formula `N(1-(1-λ)^n)`) and only holds for a homogeneous user group under iterative testing; now attributed with assumptions stated. (2) The A/B testing sample-size "Quick Reference Table" in `ab-testing-implementation.md` was internally inconsistent — re-deriving from the file's own stated formula (`n = 2×(Zα+Zβ)²×p(1-p)/(MDE×p)²`) showed every cell was roughly half the correct value; replaced with re-derived numbers and added a warning to verify against a calculator before committing traffic. Lesson: when a reference file states its own formula, always re-derive at least one table row before trusting the table — "shows its work" content can still contain silent arithmetic drift.
