## Choosing a Sync Workflow

There is **no single official mandate** in 2026 — three viable workflows coexist. Pick by your constraint, not by fashion.

| Workflow | Use when | Trade-off |
|----------|----------|-----------|
| **Rojo + VS Code** | Git-native team, CI/CD, large codebase | Battle-tested; **does not work with Team Create**; filesystem-first |
| **Script Sync** (Full Release) | You need Team Create + external editor | Roblox-native, resumes on restart, scales to ~10k scripts; **syncs scripts only**, not Models/Parts. Confirmed Full Release ~late Jun 2026 (DevForum "[Full Release] Studio Script Sync"), adding conflict resolution, safer file deletion, a simplified sync workflow, and Team Create sync indicators over the beta |
| **Azul + Rokit + Wally** | Want external editing without Rojo's project-file overhead | Studio-first, infers structure; newer, community-maintained (2026) |

DURABLE: the choice axis (Team Create support vs git-native rigor). VOLATILE: which tools are in beta and their exact limits.

## Rojo + Rokit + Wally (git-native)

The dominant production stack for serious projects.

1. **Install the tool manager — Rokit** (successor to the deprecated Aftman):
   ```bash
   rokit add rojo-rbx/rojo
   rokit install
   ```
2. **Scaffold the project:**
   ```bash
   rojo init
   ```
   This generates `default.project.json` and a `src/` layout.
3. **Serve and connect:** run `rojo serve`, then connect from the Rojo Studio plugin. Edits round-trip Studio ↔ disk on save.
4. **Version control** the filesystem with git as you would any codebase.

VOLATILE: command surface and plugin UI can change across Rojo majors — verify against the current Rojo docs.

## Script Sync (Team Create compatible)

Roblox's built-in answer to external editing (launched Beta late 2025, reached **Full Release Jun 2026**). Syncs `Script`, `LocalScript`, `ModuleScript`, and `Folder` instances to `.lua`/`.luau` files on disk, supports folder-level sync, resumes automatically on Studio restart, and — critically — **works with Team Create**, which Rojo does not.

Limitations (`as of Jul 2026 — verify`): cannot sync non-script instances (Models, Parts); no full project-structure management. Known post-release edge cases: "ghost instances" in Team Create, and scripts nested under non-Folder/non-Script ancestors can be silently skipped — confirm every script actually round-trips.

Use it when collaborative in-Studio editing (Team Create) is non-negotiable and you still want to edit scripts in VS Code.

## default.project.json

A JSON file mapping the on-disk tree to the Roblox DataModel — e.g. `src/server/` → `ServerScriptService`, `src/shared/` → `ReplicatedStorage`, `src/client/` → `StarterPlayer/StarterPlayerScripts`. Required by Rojo (auto-generated by `rojo init`); not needed for Azul or Script Sync, which infer structure.

Keep the realm split clean:
- `ServerScriptService` / `ServerStorage` — server-only logic and assets the client must never receive.
- `ReplicatedStorage` — shared modules and assets both realms need (kept lean; never streams).
- `StarterPlayerScripts` / `StarterGui` — client code and UI.

## Package and Build Tooling

| Tool | Role | Analogue |
|------|------|----------|
| **Rokit** | Toolchain version manager | `asdf` / `volta` |
| **Wally** | Package manager (`wally.toml`, `[dependencies]` + `[server-dependencies]`) | `npm` / `cargo` |
| **Lune** | Standalone Luau runtime for build scripts, CI, place-file manipulation | `package.json scripts` runner |
| **Argon** | Community Rojo alternative with two-way instance+property sync | — |

DURABLE: Rokit + Wally + Lune as the git-native automation trio. VOLATILE: Argon's relative maturity vs Rojo.

## AI-Assisted Creation

In 2026, "create a world" legitimately includes AI tooling. What is **shipping** vs hype:

| Feature | Status (May 2026) | Use |
|---------|-------------------|-----|
| **Code Assist** | GA | In-editor Luau completion, explanation, insertion; works with Team Create |
| **Material Generator** | GA, all developers | Text prompt → Material Variant with full PBR maps (Color/Normal/Roughness/Metalness) |
| **Assistant (chat + planning mode)** | Shipping | In-Studio AI chat; planning mode generates task lists; procedural model generation |
| **Studio MCP server** | Shipping | Studio exposes an MCP server so external LLMs (Claude Code, Cursor) can drive Studio |
| **Assistant playtest agent** | **Beta** | Automated QA-style playtesting against the plan, code, data model, logs, and playable character |
| **Avatar Auto-Setup** | Shipping (~90% success) | AI avatar rigging |
| **Texture Generator** | **Beta** | Text prompt → 1024×1024 ColorMap for MeshParts; daily generation cap; **ColorMap only, no PBR yet** |
| **4D Objects / generative 3D** | **UNVERIFIED** | Announced; confirm shipping before depending on it |

Practical flow: use Material/Texture Generators to dress greyboxed geometry fast, Code Assist for boilerplate, and the Studio MCP server when you want an external agent to manipulate the place — but keep human authority over architecture and economy logic (the AI is for drafting, not for trusted decisions).

VOLATILE: every AI feature's status, limits, and availability — verify against the current creator roadmap and Assistant docs.

## Decision Summary

- **Solo / git-native / CI:** Rojo + Rokit + Wally + Lune.
- **Team Create required:** Script Sync (accept the script-only limitation) or stay fully in-Studio.
- **External editing, minimal config:** Azul + Rokit + Wally.
- **Always:** keep `ServerStorage`/`ServerScriptService` for anything the client must not see; keep `ReplicatedStorage` lean.
