# Primitive 02 — M/M/1 Queue (Single-Server Markovian)

**Source**: Kleinrock, L. (1975). *Queueing Systems, Vol. 1: Theory*. Wiley. Erlang, A. K. (1909). "The Theory of Probabilities and Telephone Conversations." *Nyt Tidsskrift for Matematik B*, 20, 33–39 (introduces the Poisson-arrivals model this primitive relies on; distinct from Erlang's 1917 blocking-probability paper used in primitives 03 and 10).

## Definition

The **M/M/1 queue** is the simplest single-server queuing model:

- **M** (Markovian arrivals): Poisson process, rate λ. Inter-arrival times are exponentially distributed.
- **M** (Markovian service): Exponential service times, rate μ.
- **1** server.
- Infinite buffer capacity (queue does not drop).

**Traffic intensity (server utilization)**:

```
ρ = λ / μ
```

System is stable only when **ρ < 1** (arrival rate strictly less than service rate).

### Key Metrics

| Metric | Formula | Meaning |
|--------|---------|---------|
| Mean items in system | L = ρ / (1 − ρ) | Average occupancy |
| Mean items in queue | Lq = ρ² / (1 − ρ) | Waiting, not being served |
| Mean time in system | W = 1 / (μ − λ) | End-to-end latency |
| Mean wait in queue | Wq = ρ / (μ − λ) | Time before service starts |
| Probability n in system | P(N=n) = (1−ρ) × ρⁿ | Geometric distribution |

## When to Use

- **Prototype capacity model**: first-pass estimate for a single-threaded service, single database connection pool, single-process worker.
- **Understanding saturation curves**: demonstrates how latency degrades hyperbolically as ρ → 1.
- **Baseline before upgrade to M/M/c**: if c=1 is not enough, extend to multi-server.

Do NOT use M/M/1 when ρ ≥ 0.8 without USL retrograde check (primitive 09), or when service times are highly variable (CV > 1) — use M/G/1 (primitive 04) instead.

## Inputs

| Input | Symbol | Typical source |
|-------|--------|----------------|
| Arrival rate | λ | Requests/sec from telemetry |
| Service rate | μ | 1 / mean_service_time from profiling |

## Outputs

- **ρ** (utilization) — primary health indicator.
- **W** (mean latency) — end-to-end prediction.
- **Lq** (mean queue length) — memory/buffer sizing.
- **P(N > k)** — probability of queue exceeding k items (tail risk).

## Failure Modes

| Failure | Cause | Fix |
|---------|-------|-----|
| ρ ≥ 1 assumed stable | λ ≥ μ means unbounded queue | Scale up μ or shed load; system cannot stabilize |
| Using M/M/1 at ρ = 0.9 without concern | Latency is 10× vs ρ = 0.5 — hyperbolic blowup | Model tail latency explicitly; plan headroom ρ ≤ 0.7 |
| Ignoring service-time variance | CV² > 1 inflates actual latency beyond M/M/1 prediction | Switch to M/G/1 / Kingman (primitives 04, 07) |
| Infinite buffer assumed OK | Real systems drop, timeout, or backpressure | Add loss model (Erlang-B, primitive 10) or finite-buffer |

## Worked Example

A microservice receives **200 req/s** (λ = 200). Mean service time is **4 ms**, so μ = 250 req/s.

```
ρ = 200 / 250 = 0.80
L  = 0.80 / (1 − 0.80) = 4.0 requests
W  = 1 / (250 − 200)   = 0.020 s = 20 ms
Wq = 0.80 / (250 − 200) = 0.016 s = 16 ms (waiting time alone)
```

At 80% utilization, mean latency is already 5× the raw service time (4 ms → 20 ms). If λ increases to 240 req/s (ρ = 0.96), W jumps to 100 ms — a 5× further degradation from a 20% traffic increase.

This non-linear sensitivity is the central insight of M/M/1: **plan capacity for ρ ≤ 0.70 to maintain latency headroom**.

## Composition

- **Little's Law** (primitive 01): L = λ × W; use to verify derived metrics.
- **M/M/c** (primitive 03): extend to c servers when single server cannot meet ρ target.
- **Kingman's formula** (primitive 07): when service times are not exponential (CV ≠ 1), use Kingman for G/G/1 approximation.
- **USL** (primitive 09): check whether adding parallel capacity actually scales.
